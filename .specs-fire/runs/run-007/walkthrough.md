# Implementation Walkthrough: 구독 스트림 및 AOI 조회 경로 구현

## Summary
AOI/stream 구독 경로를 `subscriptions` 하위 4개 모듈로 분리해 위치/건설/전투/인벤토리 쿼리를 독립적으로 구성할 수 있게 했다. `AoiFilter`를 공통 입력으로 도입해 region/bounds 기반 필터를 표준화했고, 전체 구독 대신 선택적 구독 query builder를 제공했다. 신규 쿼리 빌더는 단위 테스트로 필터 절 포함 여부를 검증했다.

## Structure Overview
구독 로직은 reducer와 분리된 helper 계층으로 두고, 클라이언트가 필요한 도메인 쿼리만 조합해서 구독하도록 설계했다. AOI 기준(지역+좌표 범위)은 `aoi` 모듈에서 캡슐화하고, building/combat/inventory 모듈은 해당 필터 또는 주체(owner/container) 기반으로 SQL 구독 문자열을 생성한다. `subscriptions/mod.rs`는 외부에서 사용하는 통합 API 진입점을 제공한다.

## Key Implementation Details

### 1. AOI filter normalization
`AoiFilter::new`에서 bounds 유효성을 검증하고, region/hex 조건 문자열 생성을 공통화했다.

### 2. Domain-specific selective streams
- Building: `building_state`, `claim_state`
- Combat: `combat_state`, `attack_outcome`
- Inventory: `inventory_container`, `inventory_slot`, `item_instance/item_stack/item_def` join
각 모듈은 필요한 테이블만 구독하도록 쿼리 함수를 제공한다.

### 3. Test-backed query safety
각 모듈 테스트는 최소 필터 절(region/bounds/owner/container/limit/join) 포함 여부를 확인해 broad query 회귀를 방지한다.
