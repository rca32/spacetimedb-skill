# Implementation Walkthrough: 정적 데이터 로더 및 에셋 파이프라인 구축

## Summary
`crates/data_loader`를 신규 추가해 item/building/combat/quest CSV 파싱과 스키마 검증 경로를 구현했다. `game_server`의 `import_csv_data`/`import_csv_by_type` reducer를 실제 import 파이프라인으로 교체하고, 정적 데이터 정의 테이블을 추가해 도메인별 적재를 가능하게 했다. `assets/static_data` 구조도 설계 문서 기준으로 생성했다.

## Structure Overview
정적 CSV는 `stitch-server/assets/static_data`에 도메인별로 배치되고, `game_server`에서 `include_str!`로 내장된다. reducer는 먼저 `data_loader`의 파서/검증 함수를 호출해 데이터를 검증하고, 검증 통과 시에만 각 테이블에 idempotent upsert를 수행한다. building/quest 데이터는 item 참조 무결성까지 검사해 잘못된 참조를 import 단계에서 차단한다.

## Key Implementation Details

### 1. Strict CSV schema validation in `data_loader`
각 도메인 CSV는 필수 컬럼 누락, 타입 불일치, 중복 ID, 0/음수 제약 위반을 `Err`로 반환한다. 이로써 malformed 데이터가 reducer mutation 단계까지 내려오지 않도록 했다.

### 2. Static data tables for non-item domains
`building_def`, `combat_action_def`, `quest_chain_def` 테이블을 추가해 item 외 도메인도 import 후 SQL/구독 대상으로 활용 가능하게 했다.

### 3. Idempotent import reducers with referential checks
`import_csv_by_type`는 `items/buildings/combat/quests/all`을 지원하며, 기존 key가 있으면 교체(upsert)하고 building/quest는 `item_def` 참조 유효성을 검증한다.

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| CSV 로딩 방식 | `include_str!` 정적 내장 | SpacetimeDB 모듈 런타임에서 파일 I/O 의존 없이 일관된 import 보장 |
| 검증 위치 | `data_loader`에서 선검증 | reducer mutation 전에 실패시켜 스키마 오염 방지 |
| 비-item 정적데이터 저장 | 전용 table 추가 | import 결과를 명시적으로 조회/검증 가능하게 하기 위해 |
