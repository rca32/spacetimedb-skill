## 2) 주요 구현 내용
- [x] `SyncEngine` 클래스로 동기화 로직 분리
  - 파일: `web-client/src/runtime/sync-engine.ts`, `web-client/src/runtime/sync.ts`
  - 내용:
    - 입력/전송/피드백/rollback-replay를 `SyncEngine` 단일 경계로 통합
    - `sync.ts`는 이벤트 바인딩/런타임 브리지 역할로 단순화

- [x] 예측-재생(rollback/replay) 기반 보정 경로 정착
  - 자료구조:
    - `SeqRingBuffer<InputCommand>`
    - `SeqRingBuffer<PredictedState>`
  - 동작:
    - feedback seq 기준으로 authoritative rollback 후 미확정 입력 재생
    - accepted feedback는 ack/큐 정리를 항상 수행하고, 보정 적용만 안정성 게이트로 제어

- [x] request_id 안정화 (서버 64자 제한 대응)
  - 서버 제약: `request_id <= 64`
  - 변경:
    - `mv:<boot_nonce>:<session_counter>:<seq>` 포맷 사용
    - 하드 상한 64 적용 (`Math.min(64, configuredMax)`)

- [x] 세션 격리(Session Isolation) 버그 수정
  - 문제:
    - 파서가 session 파트를 무시해 이전 세션 feedback가 현재 세션 ack에 섞일 수 있었음
  - 수정:
    - `(nonce, session, seq)` 모두 일치할 때만 feedback 처리

- [x] timeout 경고 레이트리밋/샘플링
  - 변경:
    - `pending movement request expired` 경고를 최소 간격으로 제한
    - 억제된 건수 `expiredSinceLastLog` 동시 출력
  - 설정:
    - `VITE_SYNC_PENDING_WARN_MIN_INTERVAL_MS` (기본 1500ms)

- [x] HUD 진단 라인 추가 (`SYNCDBG`)
  - 파일: `web-client/src/ui/hud/index.ts`, `web-client/src/runtime/ui.ts`, `web-client/src/runtime/types.ts`
  - 노출 값:
    - `ack/sent`, `pending`, `timeoutExpired`
    - skip 카운터(`session`, `identity`, `old/dup`)

- [x] 문서 반영
  - 파일: `WEBCLIENTDESIGN/03-sync-prediction.md`
  - 반영 항목:
    - request_id 최신 규칙
    - ring buffer + rollback/replay 모델
    - session 격리 규칙
    - timeout 로그 레이트리밋 정책
    - HUD `SYNCDBG` 규칙

## 3) 디버깅 과정에서 확인한 이슈
- `movement-request-log` 구독 시도는 실패
  - 에러: `no such table: movement_request_log`
  - 조치: fallback/구독 코드 제거, 공개 view 기반 경로로 복귀

- SQL 제약 확인
  - `IN`, `ORDER BY` 등 일부 구문이 환경에서 제한적으로 동작
  - 디버깅 쿼리는 단순 `WHERE request_id = '...'` 형태로 검증

## 5) 현재 상태 요약
- Sync 경로는 patch형 if-guard 누적 구조에서 rollback/replay 기반으로 정리됨.
- request_id 길이 및 세션 오염 이슈는 코드/테스트로 차단됨.
- 운영 중 로그 노이즈는 레이트리밋으로 완화되고, HUD에서 동기화 내부 상태를 즉시 확인 가능.
