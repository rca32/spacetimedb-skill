# 2026-02-20 Plan

## Stitch Building System Orillusion 적용 계획

### 1. 요약
- 기준 문서: `DESIGN/DETAIL/building-system-design.md`
- 목표: 현재 `stitch-server` + `stitch-orillusion-client` 기준에서, 설계 문서의 건축 시스템을 Orillusion 클라이언트에 단계적으로 반영한다.
- 우선 버티컬 슬라이스: `배치 선택(Pick) -> 서버 Preview 검증 -> 확정 배치`
- 범위: 현 스키마 유지가 아니라, 설계 기준 확장(`project_site_state`, `building_footprint`, preview API)까지 포함한다.

### 2. 현재 상태 기준선
1. 서버 구현 상태
- 존재: `building_state`, `claim_state`, `building_place`, `building_advance`, `building_deconstruct`, `claim_totem_place`
- 미구현(설계 대비): `project_site_state`, `building_footprint`, `building_validate_preview`, chunk 단위 preview 스트림

2. 클라이언트 구현 상태 (`stitch-orillusion-client`)
- `building_state`를 단순 박스로 렌더링
- 배치 모드, 선택, 미리보기 ghost, 건설 액션 UI 미구현
- pick 설정 비활성: `Engine3D.setting.pick.enable = false`

3. 동기화 상태
- AOI 구독으로 `building_state`는 수신 중
- build mode 기반 선택적 구독 분기 없음

### 3. 규칙 적용 매핑 (Skills)

#### 3.1 Orillusion Best Practices
- `setup-engine-setting-before-init`
  - `Engine3D.setting.*` 핵심값은 `Engine3D.init` 이전 고정
- `core-single-render-loop-contract`
  - 입력/preview 갱신은 단일 렌더 루프 또는 Script `onUpdate`로 통합
- `core-pick-mode-choice`
  - 기본 `bound`, 정밀 선택 필요 시 `pixel` 옵션 분리
- `render-pbr-default`
  - 건축물 본체는 Lit 중심, preview/debug는 Unlit 제한 사용
- `resource-use-res-cache`
  - 모델/텍스처/재질 재사용은 `Engine3D.res` 캐시 우선
- `lifecycle-avoid-force-destroy-on-shared`
  - 공유 geometry/material에 `destroy(true)` 금지

#### 3.2 SpacetimeDB Korean Best Practices
- `table-indexing`
  - AOI/preview 필터 컬럼 인덱스 보강
- `reducer-validation`
  - reducer 진입 시 입력/권한/거리/dimension 검증 선행
- `subscription-selective`
  - build mode ON일 때만 preview/footprint 관련 구독 활성화

### 4. 공개 API / 스키마 변경 계획

#### 4.1 서버 리듀서 추가
- `building_validate_preview(building_def_id, region_id, dimension_id, hex_x, hex_z, facing) -> PlacementPreview`
- `building_place_from_preview(request_id, building_def_id, region_id, dimension_id, hex_x, hex_z, facing) -> building_id`
- 기존 `building_place(_in_dimension)`은 하위 호환 유지

#### 4.2 서버 테이블 추가
- `project_site_state`
  - 프로젝트 진행 상태(소유자, 위치, 방향, 진행도, 상태)
- `building_footprint`
  - 배치된 footprint/perimeter 타일의 런타임 점유 상태
- `building_preview_feedback_view`
  - 클라이언트 즉시 피드백용 축약 결과(요청별 validity/error)

#### 4.3 인덱스 계획
- `building_state`: `(region_id, dimension_id, hex_x, hex_z)`, `owner_identity`
- `project_site_state`: `(region_id, dimension_id, hex_x, hex_z)`, `owner_identity`
- `building_footprint`: `(region_id, dimension_id, hex_x, hex_z)`, `building_entity_id`
- `claim_state`: `(region_id, dimension_id, center_x, center_z)`

### 6. 단계별 구현 순서

1. 서버 스키마/리듀서 확장
- `project_site_state`, `building_footprint`, preview reducer 및 feedback view 구현
- 기존 reducer와 충돌 없이 신규 경로 추가

2. AOI 및 선택 구독 분기
- 일반 모드: 기존 world 스트림 유지
- build mode: preview/footprint/project 구독 추가
- 모드 해제 시 unsubscribe 정리

3. Pick 기반 배치 모드 도입
- `view.pickFire` 중심 이벤트 라우팅
- 클릭 지점 hex 변환 후 preview 요청
- ghost preview(valid/invalid 색상) 렌더

4. 확정 배치 경로 연결
- confirm 시 `building_place_from_preview` 호출
- 성공 시 authoritative row 반영
- 실패 시 preview feedback 메시지 UI 반영

5. 건설 진행/철거 루프 연결
- 선택된 건축물 대상으로 `building_advance`, `building_deconstruct` 호출
- 권한/상태 기반 버튼 가드

6. 성능/수명주기 정리
- 공유 리소스 캐시화
- object 파괴 시 shared resource 안전 해제 정책 적용

### 7. 테스트 시나리오 및 수용 기준

1. 기능
- 유효 위치: preview valid -> place 성공 -> `project_site_state`/`building_state` 반영
- 무효 위치: preview invalid + 에러 코드 일치
- dimension 전환 시 타 차원 데이터 혼입 없음

2. 구독
- build mode OFF: footprint/preview 관련 구독 비활성
- build mode ON: 관련 구독 활성 및 AOI 경계 반영
- 모드 전환 반복 시 중복 구독 누적 없음

3. 상호작용
- bound pick 기본 정상
- 복잡 객체에서 pixel pick 전환 옵션 정상
- 클릭-회전-확정 루프에서 위치 불일치 없음

4. 안정성/성능
- 장시간 배치 반복 시 메모리 급증 없음
- `destroy(true)` 미사용 상태 유지
- 목표 FPS 하한(로컬 기준) 이탈 시 DPR/postfx 프로파일 조정 가능
