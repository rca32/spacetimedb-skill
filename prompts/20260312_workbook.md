## 이번 작업의 핵심 판단

- 기존 `2DGameEngine` 문서군에는 이미 아키텍처, sync pipeline, 도메인별 설계가 충분히 있으므로, 이번에는 그 위에 `우선순위별 실행 문서`를 추가하는 편이 중복이 적다.
- `DESIGN`은 테이블/권한/도메인 모델의 기준선으로 사용하고, 현재 `2DGameEngine` 문서에 적힌 reducer/helper 이름을 stitch-server 연동 포인트로 사용했다.
- SpacetimeDB 연결 계획에는 스킬 지침에 따라 `bindings 선생성`, `선택적 구독`, `subscription applied 이후 ready 판정`을 반영했다.

## 우선순위별 설계 메모

### 1. `web-client` 프로젝트 생성

- `bun` + TypeScript + PixiJS v8를 기준으로 workspace 구조를 먼저 고정한다.
- Spacetime TypeScript bindings 생성 스크립트를 초기에 분리해 이후 reducer/query 변경 대응 비용을 줄인다.

### 2. Pixi bootstrap

- `Application.init`, resize, ticker, stage/layer 구조를 먼저 잡아야 이후 terrain/entity/HUD 작업이 충돌하지 않는다.
- subscription callback이 Pixi scene을 직접 만지지 않는 구조를 초기에 박아두는 것이 중요하다.

### 3. AssetPack/seed asset

- `assetdirectory`에 정리된 seed asset을 바로 쓰되, `web-client`에는 build input 규칙만 두고 직접 강결합하지 않게 설계했다.
- `boot`, `ui-core`, `ui-input-prompts`, `audio-core`, `world-common` 번들을 초기 기준으로 삼았다.

### 4. Spacetime 연결과 store

- baseline은 `player_session_view`다.
- world 구독은 `terrain_chunk`, `transform_state`, `resource_node`, `building_state`, `claim_state`, `npc_state`를 축으로 잡았다.
- 개인 projection은 `player_inventory_*_view` 세트를 별도 그룹으로 분리했다.

### 5. terrain/chunk renderer

- `DESIGN`의 `terrain_chunk`를 기준 테이블로 삼고, 현재 helper 계약의 `terrain_chunk_payload`는 decoder adapter 경계에서 수용하도록 적었다.
- entity 표시 기준은 `transform_state` 좌표와 domain snapshot 조합으로 정리했다.

### 6. movement prediction/reconciliation

- 레거시 `move_to`와 `player_movement_feedback_view`를 fallback으로 두고, 목표 경로는 `sync_client_frame`, `submit_motion_intent`, `physics_state`, `server_correction`, `ack_server_correction`으로 정리했다.
- correction reason을 HUD에 바로 드러내는 UX 원칙을 넣었다.

### 7. Pixi HUD/action bar/sound

- `@pixi/layout`, `@pixi/ui`, `@pixi/sound`, `pixi-filters`를 각각 어떤 역할로 쓸지 다시 명시했다.
- DOM은 채팅/긴 대화/설정처럼 텍스트와 접근성이 중요한 영역에 남긴다.

### 8. inventory/building preview

- 인벤토리는 `player_inventory_*_view` authoritative overwrite 원칙을 유지한다.
- 건설 preview는 `building_validate_preview`와 `building_preview_feedback_view`를 기준으로 색상/사유를 갱신하도록 정리했다.
- `claim_state`와 `permission_state`를 분리해 표시해야 한다는 점을 강조했다.

### 9. combat/NPC/social

- 전투는 local anticipation과 authoritative damage confirm을 분리했다.
- NPC는 actor state와 dialogue session을 분리 저장하는 방향으로 적었다.
- 소셜은 `chat`, `party`, `guild`, `social_feed`를 world sync와 분리한 별도 subscription 그룹으로 정리했다.

## 현재 상태 판단

- placeholder `src/module_bindings/index.ts` 의존 단계는 끝났고, 현재 `web-client`는 실제 generated bindings 기준으로 컴파일된다.
- movement 쪽은 더 이상 purely local debug loop가 아니라 서버 reducer 호출과 authoritative feedback/correction 소비까지 연결된 상태다.
- 월드 렌더/HUD는 seed texture와 generated row naming 기준으로 정리됐고, world subscription도 session/anchor 기반 재구독 구조까지 들어갔다.
- 브라우저 런타임도 실제로 부팅되며, canvas와 HUD 카드가 같이 렌더되고 interactive controls가 노출되는 상태를 확인했다.
- 이번 단계로 seed frame 선택 규칙 세분화, `request_chunks_for_aoi` 연결, inventory/building/reducer vertical slice UI까지 들어갔다.
- seed frame 선택은 이제 public def table 기반으로 내려오고, claim overlay와 pointer picking 기본 UX도 붙었다.
- world loading은 이제 실제 live session/token 기준으로도 검증됐다.
- live world loading의 큰 병목은 일단 줄였고 실제 world tile도 보이기 시작했다.
- 남은 핵심은 debug HUD가 viewport를 많이 가리는 점을 정리하는 것, building preview reducer round-trip을 live 세션에서 더 깊게 검증하는 것, inventory live round-trip 확장, 그리고 heuristic fallback을 제거할 전용 render metadata 계층 설계다.
