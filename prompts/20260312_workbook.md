## 이번 작업의 핵심 판단

- 기존 `2DGameEngine` 문서군에는 이미 아키텍처, sync pipeline, 도메인별 설계가 충분히 있으므로, 이번에는 그 위에 `우선순위별 실행 문서`를 추가하는 편이 중복이 적다.
- `DESIGN`은 테이블/권한/도메인 모델의 기준선으로 사용하고, 현재 `2DGameEngine` 문서에 적힌 reducer/helper 이름을 stitch-server 연동 포인트로 사용했다.
- SpacetimeDB 연결 계획에는 스킬 지침에 따라 `bindings 선생성`, `선택적 구독`, `subscription applied 이후 ready 판정`을 반영했다.

## 문서에 반영한 구현 우선순위

## 우선순위별 설계 메모

### 1. `web-client` 프로젝트 생성

- `bun` + TypeScript + PixiJS v8를 기준으로 workspace 구조를 먼저 고정한다.
- Spacetime TypeScript bindings 생성 스크립트를 초기에 분리해 이후 reducer/query 변경 대응 비용을 줄인다.

### 2. Pixi bootstrap

- `Application.init`, resize, ticker, stage/layer 구조를 먼저 잡아야 이후 terrain/entity/HUD 작업이 충돌하지 않는다.
- subscription callback이 Pixi scene을 직접 만지지 않는 구조를 초기에 박아두는 것이 중요하다.

### 3. AssetPack/seed asset

- `assetdirectory`에 정리된 seed asset을 바로 쓰되, `web-client`에는 build input 규칙만 두고 직접 강결합하지 않게 설계했다.
- `boot`, `ui-core`, `ui-input-prompts`, `audio-core`, `world-common` 번들을 초기 기준으로 삼았다.

### 4. Spacetime 연결과 store

- baseline은 `player_session_view`다.
- world 구독은 `terrain_chunk`, `transform_state`, `resource_node`, `building_state`, `claim_state`, `npc_state`를 축으로 잡았다.
- 개인 projection은 `player_inventory_*_view` 세트를 별도 그룹으로 분리했다.

### 5. terrain/chunk renderer

- `DESIGN`의 `terrain_chunk`를 기준 테이블로 삼고, 현재 helper 계약의 `terrain_chunk_payload`는 decoder adapter 경계에서 수용하도록 적었다.
- entity 표시 기준은 `transform_state` 좌표와 domain snapshot 조합으로 정리했다.

### 6. movement prediction/reconciliation

- 레거시 `move_to`와 `player_movement_feedback_view`를 fallback으로 두고, 목표 경로는 `sync_client_frame`, `submit_motion_intent`, `physics_state`, `server_correction`, `ack_server_correction`으로 정리했다.
- correction reason을 HUD에 바로 드러내는 UX 원칙을 넣었다.

### 7. Pixi HUD/action bar/sound

- `@pixi/layout`, `@pixi/ui`, `@pixi/sound`, `pixi-filters`를 각각 어떤 역할로 쓸지 다시 명시했다.
- DOM은 채팅/긴 대화/설정처럼 텍스트와 접근성이 중요한 영역에 남긴다.

### 8. inventory/building preview

- 인벤토리는 `player_inventory_*_view` authoritative overwrite 원칙을 유지한다.
- 건설 preview는 `building_validate_preview`와 `building_preview_feedback_view`를 기준으로 색상/사유를 갱신하도록 정리했다.
- `claim_state`와 `permission_state`를 분리해 표시해야 한다는 점을 강조했다.

### 9. combat/NPC/social

- 전투는 local anticipation과 authoritative damage confirm을 분리했다.
- NPC는 actor state와 dialogue session을 분리 저장하는 방향으로 적었다.
- 소셜은 `chat`, `party`, `guild`, `social_feed`를 world sync와 분리한 별도 subscription 그룹으로 정리했다.

## 실제 구현 시작 결과

- `web-client/package.json`, `tsconfig.json`, `bunfig.toml`, `.env.example`로 앱 기본 골격을 만들었다.
- `web-client/src/main.ts`에서 `bootstrapApp`으로 진입하고, 브라우저 shell 위에 Pixi canvas와 DOM HUD를 같이 올리는 구조를 만들었다.
- `web-client/src/engine/runtime/game-runtime.ts`에서 Pixi bootstrap, frame clock, debug HUD, connection bootstrap 흐름을 묶었다.
- `web-client/src/engine/net/spacetime-client.ts`에는 Spacetime `DbConnection.builder().withUri().withDatabaseName()` 흐름을 감싼 래퍼를 넣었다.
- `web-client/src/engine/net/subscription-coordinator.ts`에는 `player_session_view`, 월드 테이블군, `player_inventory_*_view` 구독 그룹과 raw SQL bootstrap query를 넣었다.
- `web-client/src/engine/state/authoritative-store.ts`에는 테이블별 row count와 upsert/delete를 처리하는 최소 authoritative cache를 넣었다.
- `web-client/src/module_bindings/index.ts`에는 실제 codegen 전에도 앱이 부팅되도록 placeholder bindings를 넣었다.
- `web-client/scripts/generate-bindings.sh`와 `web-client/scripts/stage-seed-assets.sh`를 추가해 bindings 생성과 seed asset 스테이징 시작점을 마련했다.
- `web-client/assetpack/assetpack.config.ts`에 `boot`, `ui-input-prompts`, `audio-core`, `world-common` 번들 초안을 넣었다.

## 1, 2, 3번 후속 구현 결과

- bindings 생성 스크립트의 기본 모듈 경로를 `stitch-server/crates/game_server`로 고쳤다.
- `terrain_chunk_stream`, `terrain_chunk_payload`, `player_wallet_view`를 bootstrap 구독 세트에 추가해 실제 공개 테이블 구성과 더 맞췄다.
- `web-client/src/engine/render/world-renderer.ts`를 추가해 `terrain_chunk_stream`과 `terrain_chunk_payload`를 기준으로 청크 사각형, resource/building/npc placeholder, `transform_state` actor 점을 Pixi에 그리도록 했다.
- `web-client/src/engine/render/terrain-payload-decoder.ts`를 추가해 `cell_payload_bytes` little-endian `i16` 디코딩과 `cell_payload` 직접 디코딩을 모두 수용하도록 했다.
- `web-client/src/ui/hud/inventory-hud.ts`를 추가해 `player_session_view`, `player_wallet_view`, `player_inventory_container_view`, `player_inventory_slot_view`, `player_inventory_item_view`를 DOM HUD 카드에 표시하도록 했다.
- `AuthoritativeStore`에는 raw row 조회용 `getRows()`를 추가해 renderer와 HUD가 같은 authoritative 캐시를 읽게 했다.
- 실제 산출물 확보를 위해 `stage-seed-assets.sh`와 `generate-bindings.sh`를 실행했다. 이 실행은 응답 시점에도 셸에서 계속 진행 중일 수 있다.

## 재개 후 구현 결과

- `web-client/package.json`의 `spacetime:generate`, `assets:stage` 스크립트를 `bash ./scripts/...` 형태로 바꿔 실행 비트가 없어도 `bun run`으로 동작하게 정리했다.
- `bun install`을 완료해 `web-client/bun.lock`과 로컬 의존성을 설치했고, 이후 `bun run build`가 정상 동작하는 상태를 만들었다.

- `bun run spacetime:generate`를 다시 실행해 `web-client/src/module_bindings/*` 실제 generated bindings를 생성했다.
- 생성 결과에 `physics_state`, `player_movement_feedback_view`, `server_correction`, `submit_motion_intent`, `sync_client_frame`, `ack_server_correction`이 포함되는 것을 확인했다.
- `web-client/src/engine/shared/row-access.ts`를 추가해 generated row의 camelCase 필드와 기존 snake_case 참조를 함께 읽을 수 있는 공통 접근 유틸을 만들었다.
- `web-client/src/engine/state/authoritative-store.ts`의 row key 추론을 generated camelCase primary key에도 맞게 보강했다.
- `web-client/src/engine/net/subscription-coordinator.ts`는 `player_session_view`, `player_wallet_view`, `player_inventory_*_view`, `player_movement_feedback_view`, `server_correction`, `physics_state`를 identity 기준 selective query로 구독하도록 바꿨다.
- `web-client/src/engine/prediction/movement-prediction-runtime.ts`는 `sync_client_frame`, `submit_motion_intent`, `physics_state`, `player_movement_feedback_view`, `server_correction`, `ack_server_correction` 흐름을 사용한 reconciliation 루프로 확장했다.
- `web-client/src/ui/hud/inventory-hud.ts`, `web-client/src/engine/render/terrain-payload-decoder.ts`, `web-client/src/engine/render/world-renderer.ts`는 generated bindings row naming 기준으로 다시 맞췄다.

## 현재 상태 판단

- placeholder `src/module_bindings/index.ts` 의존 단계는 끝났고, 현재 `web-client`는 실제 generated bindings 기준으로 컴파일된다.
- movement 쪽은 더 이상 purely local debug loop가 아니라 서버 reducer 호출과 authoritative feedback/correction 소비까지 연결된 상태다.
- 월드 렌더/HUD는 generated row naming과 맞도록 정리됐지만, sprite atlas frame 선택과 AOI 단위 selective world query는 아직 남아 있다.
